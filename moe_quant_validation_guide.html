Project Guide

MatmulFreeLLM 量化方案在 MoE 架构下的验证指导

本文件用于指导当前项目的实验设计、阶段验收、失败迭代和最终汇报。 后续在本对话内继续推进该项目时，应优先读取本文件并以此为默认基线。

1. 项目目标

验证 MatmulFreeLLM 当前采用的量化方案，即 activation per-token int8 fake quant + ternary weight {-1,0,1} + STE， 能否在 MoE 架构中有效工作，并在可接受范围内不带来明显精度损失。

一级目标 仅量化 expert MLP，验证主任务精度是否保持稳定。
二级目标 在一级目标成立后，再探索 lm_head 或 shared FFN 的进一步量化。
非一期目标 不把 router 三值化、attention 全路径三值化作为第一阶段硬目标。
推荐先将“可接受范围”固定为：相对 FP/BF16 MoE baseline， validation perplexity 劣化不超过 3%~5%， 且无明显 expert collapse、无训练发散。

2. 验收总标准

  • 主指标：相对 FP/BF16 MoE baseline，验证集 ppl 劣化不超过 3%；若存在下游任务，绝对分数下降不超过 1 个点或相对下降不超过 2%。
  • 稳定性：训练过程中无 NaN、Inf、持续性 loss 发散。
  • 路由质量：无明显 expert collapse，expert token 分布不过度偏斜。
  • 收敛效率：达到目标指标的训练步数不超过 baseline 的 1.3x。
  • 结论质量：至少在多个随机种子下可重复，不能只依赖单次幸运结果。

3. 项目执行流程

阶段 阶段目标 执行内容 验收标准 不通过时的自我迭代方案
Phase 0 锁定实验基线 确定数据集、模型规模、专家数、top-k、训练步数、优化器、学习率、日志格式、随机种子。 后续实验共享统一训练配方，避免基线漂移。 如配置尚未稳定，暂停量化验证，先只做基线训练收敛确认。
Phase 1 建立非量化 Dense/MoE 基线 运行 Dense FP/BF16 与 MoE FP/BF16 对照实验。 MoE FP/BF16 能稳定训练，且指标合理，不出现 collapse。 优先调 router、capacity factor、load balance loss、top-k，不进入量化阶段。
Phase 2 最小量化可行性验证 仅量化 expert MLP 中的线性层；router、attention、embedding、lm_head 保持浮点。 相对 MoE FP/BF16，主指标退化在阈值内，训练稳定。 若失败，先尝试 warm-start、降低学习率、延长 warmup、增强 load balance loss、切换 top-1/top-2。
Phase 3 收敛与鲁棒性复核 多随机种子、多训练长度、多评估点复现。 结论可复现，量化版本不是偶然成功或偶然失败。 若 seed 波动大，增加训练步数，记录 router entropy、expert 负载、梯度范数，必要时采用渐进量化。
Phase 4 扩大量化边界 在 Phase 2 成功后，逐步试验 shared FFN、lm_head 等模块。 每次扩展后仍满足主指标阈值，且训练稳定。 某一步失败即回退，记录失败边界，不继续无序叠加量化范围。
Phase 5 泛化性验证 更换不同数据切片、上下文长度、专家容量或路由配置复核结论。 结论不依赖单一数据或单一超参点。 若只在局部配置有效，则明确收缩结论范围，禁止过度泛化。
Phase 6 形成最终结论 汇总通过与失败方案、成功边界、失败原因、推荐配置。 能够明确回答“在哪个量化程度下满足项目目标”。 若全部失败，则输出失败结论和最可能瓶颈，而不是模糊描述。

4. 推荐实验矩阵

  1. Dense FP/BF16 baseline
  2. MoE FP/BF16 baseline
  3. MoE + ternary expert weights + int8 activation fake quant
  4. MoE + ternary experts + warm-start from FP MoE checkpoint
  5. MoE + ternary experts + top-1 vs top-2 routing
  6. MoE + ternary experts + different load balance coefficients
  7. MoE + ternary experts + lm_head ternary
  8. MoE + ternary router，仅作为后置高风险探索项
默认优先级：先验证 expert-only quantization，后验证更激进量化，不要一开始就追求全模型三值化。

5. 每阶段必须记录的指标

  • validation loss / perplexity
  • 下游任务主指标，如 accuracy、F1、BLEU
  • load balance loss
  • 每个 expert 的 token 占比与长期利用率
  • router entropy、top-k 分布
  • 梯度范数、是否出现 NaN/Inf
  • 达到目标验证指标所需训练步数
  • 显存占用与 tokens/s

6. 失败时的优先排查顺序

  1. 先判断问题是否来自 MoE 本身，而不是量化。
  2. 再判断问题是否来自 router，而不是 expert 三值化。
  3. 再检查训练配方是否不适合量化：学习率过大、warmup 太短、aux loss 太弱。
  4. 最后才下结论说“三值量化在该位置不可用”。

7. 最终预期效果

最现实的成功形态 在 expert MLP 上应用 MatmulFreeLLM 量化方案，router 保持浮点，主指标退化不超过 3%~5%。
加分项 在一级目标成立后，lm_head 或 shared FFN 也可量化，整体仍不显著破坏精度。
暂不作为一期目标 router 三值化、attention 路径全面三值化、运行时专用 ternary kernel 加速。

项目最终需要回答的问题应当收敛为一句明确结论： 在什么量化程度下，MoE 可以稳定训练并保持可接受精度；哪些模块量化后会显著破坏性能。
